| 2026-09-24 | Implement game behavior, result submission, Firebase Firestore ranking, signed QR results, and `.env.example` in the root project only. | Extends the approved visual scope into the requested event experience without modifying `desafio-crescer2`. | Active |
| 2026-09-24 | Update the active Palavra Proibida round to show the current target in the title position and only the five forbidden words in the prompt panel. | Matches the approved gameplay hierarchy from the latest screen reference. | Active |
| 2026-09-24 | Use PageUp/PageDown for correct/skip, ArrowUp/ArrowDown for selecting the two games, and the player's headset as the only speech input. | This matches the final Air Mouse G10 Pro button layout confirmed by the user. | Active |
| 2026-09-29 | Restrict the Palavra Proibida deck to widely known saints, priests, objects, and Campina Grande churches, keeping forbidden words unchanged. | The user reported the game was too hard because of obscure names; familiarity is the simplification lever. | Active |
| 2026-09-29 | Provide the printable deck as an App Router page styled for A4 print instead of adding a PDF dependency. | Browser "Save as PDF" produces the requested file without new dependencies and always reflects the current deck. | Active |
| 2026-10-15 | Allow the operator to correct a score by submitting a negative amount, floored at a team total of zero, with each entry logged as an auditable `gameResults` record. | Live events need reversals; hiding them would push the operator to edit the database by hand. Clamping keeps the leaderboard free of negative totals, and the audit record keeps the history honest. | Active |
| 2026-10-15 | Make manual scoring idempotent per client-generated `operationId` rather than relying on the disabled button alone. | A double-click or a retried request against a live ranking adds real points; the operation record makes the retry return the original outcome instead of scoring again. | Active |
| 2026-10-15 | Keep `/admin` and `/api/admin/ranking` unauthenticated. | Explicit user decision for an event operated on a private venue network. Revisit if the panel is ever reachable from the public internet. | Active |
| 2026-10-15 | Keep the display name a team registered first instead of overwriting it on every submission. | The normalized name already identifies the team, so overwriting only lets a variant spelling degrade the public entry. A deliberate rename is a separate future feature. | Active |
| 2026-10-16 | Treat the card, not the forbidden words, as the unit that cannot repeat, and let the five forbidden words repeat freely. | The player must not meet the same target word twice, but re-meeting the same five forbidden words is the normal consequence of a larger deck and keeps `detectForbiddenWords` untouched. Filtering on the words would also make the draw depend on an approximation of what was said out loud. | Active |
| 2026-10-16 | Remember used cards in `localStorage`, keyed by category and target word instead of array position. | The round is rebuilt on every mount, so the memory has to outlive the component and the browser session. A positional key shifts whenever the deck file is edited: new cards would inherit an old card's memory and renamed cards would stay wrongly used. Content keys make adding, renaming and removing cards self-healing. | Active |
| 2026-10-16 | Deliver the operator's deck reset as a `resetDeck` control command instead of clearing storage from `/admin`. | The panel usually runs on a different device from the game screen, so a button that clears the panel's own storage would never reach the deck. The existing command channel already carries acerto/pular/erro to the running game. The clock is left running, because resetting a deck is not restarting a round. | Active |
| 2026-10-16 | Draw each card from the category that is furthest behind its own share of the deck. | Taking one card per category per pass drained the small groups first: with 57 saints against 16 churches the deck ended on 30 consecutive saints, which reads as the repetition the no-repeat rule exists to prevent. | Active |
| 2026-10-16 | Let the player choose Fácil (×1), Médio (×2) or Desafio (×3) before the Emojis dos Santos match, fixed for its eight rounds. | Difficulty is what makes the same game work both for someone who knows the saints and for a competitive team, and a fixed level keeps the score comparable across the eight rounds. | Active |
| 2026-10-16 | Derive the 10s and 20s hints from the round clock instead of scheduling separate timers, and stop the clock on a correct answer. | One interval per round means no duplicated or leaked timer, the hints cannot drift from the displayed clock, and a hint that was never reached is never shown. | Active |
| 2026-10-16 | Lock the round as soon as it is resolved so a hit scores exactly once, whatever the input source. | Voice, the Air Mouse and `/admin` can confirm the same answer within the same second; without a lock the same round would pay twice. | Active |
| 2026-10-16 | Keep the operator's `fault` outside the eight emoji rounds instead of counting it as a resolved round. | The fault exists to flag a technical or judging problem and let the team try again, so consuming a round would both stop the round from being retried and make the round count drift above eight. | Active |
| 2026-10-16 | Show an in-game end-of-match screen with replay, ranking and menu options instead of redirecting automatically. | The screen has to show the points, the hits, the non-scored rounds and the level; auto-redirecting would hide the level and force every team through the QR flow. | Active |
| 2026-10-16 | Add a `displayName` beside the normalized `name` of each saint. | The normalized name feeds the speech detector and must stay lowercase and accent-free, while the reveal has to read as a proper name. | Active |
| 2026-10-16 | Keep a separate stylesheet for the emoji screen and shrink only its emoji prompt. | `game-runtime.module.css` also styles the untouched Palavra Proibida; the emoji prompt lost some height so the level, hints, reveal and scoreboard fit one TV screen together. | Active |
| 2026-10-16 | Score Emoji dos Santos as `correct emoji combinations × level multiplier` (1, 2 or 3 points per hit), with a match maximum of 8, 16 or 24. | The score has to count the combinations the team actually guessed, multiplied by the chosen level, instead of an arbitrary 100-point base: three hits in `Médio` are `3 × 2 = 6`. The ranking keeps accumulating the score of every match. | Active |
| 2026-10-16 | Show only PONTOS and TEMPO while a round runs, and end the match by going straight to the QR Code screen. | The three-card scoreboard was crowded for a screen read from a distance, and the in-game "FIM DE JOGO" screen duplicated data the QR screen already carries. The player now reads the score in one place and is taken to the ranking step immediately; `/resultado` shows PONTOS and NÃO ACERTADAS. | Active |
